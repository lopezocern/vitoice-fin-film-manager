一句话判断

冗余不在「功能多」，而在「一条链路四份实现」：媒体数据的 读取策略有三种、状态词表有三份、列表视图有四个， 而侧边栏把这同一份数据切成了 10 个入口。

好消息是根因只有一个，改一个地方就能同时解决四套实现——见第 3 节。

03根因：缺一个谓词

所有重复都从这里长出来。

GET /media 有 25 个筛选参数，唯独没有「海报缺失 / 元数据缺失 / 无标签」

backend/app/api/media.py:344-368 支持 library / dir / type / source / file_missing / rating / duration / resolution / year / genre / country / search / sort… 但「这个媒体有没有封面」「元数据齐不齐」「有没有标签」三个状态判断不在服务端。

于是前端只能自己算：为了「算」就得先把数据「拿全」，为了让「拿全」便宜，就有了 循环拉 20 页；为了「算得不一样也不崩」，就有了三份状态词表。

而口径已经开始漂移

字段服务端 stats.py前端客户端判定结果
文件缺失 排除剧集 + 排除纯网络媒体 item.file_missing（无排除） 数量对不上
元数据待处理 排除剧集，包含网络媒体 同口径 一致
缺封面 poster_path IS NULL AND thumbnail_path IS NULL !item.poster 近似
存在问题 不存在该字段 侧边栏用三项求和 重复计数

「求和」的问题：一个媒体同时缺海报与缺元数据，会被数两次，于是侧边栏徽标永远大于实际待处理项。

backend/app/services/media_query.py· 新建
"""Shared predicates for media "issue" queries.

Single source of truth: `stats` counts and `/media` filters must never drift.
"""
from sqlalchemy import and_, exists, or_, select

from app.models.enums import MediaType
from app.models.media import Media, VideoTag


def issue_scope() -> list:
    """Rows that are eligible to be reported as an issue."""
    return [
        Media.is_deleted == False,              # 软删除不算
        Media.series_id.is_(None),               # 剧集继承父系列的海报/元数据
        Media.media_type != MediaType.NETWORK,      # 纯网络媒体天生无本地文件
    ]


def pred_missing():
    return Media.file_missing.is_(True)


def pred_no_poster():
    return and_(Media.poster_path.is_(None), Media.thumbnail_path.is_(None))


def pred_metadata_missing():
    return and_(
        Media.metadata_ignored == False,
        or_(Media.poster_path.is_(None), Media.scrape_data.is_(None)),
    )


def pred_untagged():
    return ~exists().where(VideoTag.media_id == Media.id)


def pred_problem():
    """Union, not a sum — an item missing both poster and metadata counts once."""
    return or_(pred_missing(), pred_no_poster(), pred_metadata_missing())

两边都调它

api/media.py· 插在 total count 之前
if has_poster is not None:
    query = query.where(
        ~pred_no_poster() if has_poster else pred_no_poster()

if metadata_status == "missing":
    query = query.where(pred_metadata_missing())
elif metadata_status == "ignored":

export function viewToParams(v: SavedViewId): MediaListParams {
  switch (v) {
    case 'missing':   return { file_missing: true,  exclude_series: true, exclude_network: true };
    case 'no_poster': return { has_poster: false,   exclude_series: true, exclude_network: true };
    case 'metadata':  return { metadata_status: 'missing', exclude_series: true };
    case 'ignored':   return { metadata_status: 'ignored' };
    case 'untagged':  return { untagged: true, exclude_series: true, exclude_network: true };
    case 'problem':   return { problem: true, exclude_series: true, exclude_network: true };
    default:          return {};
  }
}

13决策已定

2026-10-22 拍板，四项全部锁定；下面是决策本身与它带来的硬性后果。

1

概览页不留

删除 OverviewView(652) 与 ?section=overview，导航从 6 收敛到 5。

硬性前提：它独占的三份数据必须搬家 → 库健康进 libraries 页、最近活动进 runs、数字进 assets 顶部摘要条。
另外 GET /libraries 要补 media_count / missing_count / total_size 三个聚合（现在没有）。
2

评估有效性与效率

已用真实数据（dev 库 874 条）实测，见下一节。

结论：PR1/PR2 收益确定、风险低，建议立刻做；工作台合并值得做；共用工具栏不做（已否决，判断正确）。
3

「已忽略刮削」独立

独立成 Saved View + 独立计数，不再混在「元数据待处理」里当成一个筛选开关。

后果：stats 增加 ignored_count；PR1 从 2 个新字段变 3 个。
4

不共用工具栏

两个页面核心功能不同：媒体页是「浏览与播放」，管理页是「治理与批处理」。FilterBar(434) 保留给媒体页。

后果：共用面收窄到 query / status / useMediaList / columns；MediaToolbar 不再抽取，改为管理页专属 AssetsToolbar。目标行数从 ≤6000 修正为 ≈6300，实际落地 6500。

14有效性评估 · 实测

数据来自 dev 库（874 条媒体）直接跑谓词与序列化实测，不是估算。

先修正一个数字：不是 21 次请求

v1 写的「21 请求 / 4000 行」是代码上限（page ≤ 20 × page_size=200）。 874 条的真实值是 5 次。所以准确的问题是两段：
