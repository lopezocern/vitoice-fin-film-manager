# 媒体主页重构与多媒体能力开发方案

日期：2026-08-13  
状态：待实施  
视觉基线：`媒体主页重新设计-设计稿.html`

## 1. 目标与约束

在不破坏现有媒体扫描、系列聚合、标签、播放进度、无限滚动、受限内容、软删除和网络媒体能力的前提下，完成桌面客户端媒体主页重构，并补齐图片与音频的专用消费体验。

实施原则：

- 复用现有 `/media`、`/series`、`/player`、标签 API，不平行建设第二套媒体中心。
- 每个里程碑可独立发布和回退，主页重构不依赖歌词等后续能力。
- 分类状态进入 URL，视图和密度进入 `localStorage`，返回页面时继续复用 `mediaScroll` 恢复位置。
- 所有单资源入口继续执行软删除与受限媒体库校验。
- 桌面端优先，保留浏览器开发模式；Tauri 窗口控制复用现有实现。

## 2. 分类语义与计数口径

### 2.1 一级内容对象

| 分类 | 数据来源 | 查询口径 | 是否计入“全部媒体” |
|---|---|---|---|
| 全部 | Media + Series 混合视图 | Series 聚合项 + `series_id IS NULL` 的 Media | 是，不重复计算单集 |
| 电影 | Media | `content_kind=movie`，且 `series_id IS NULL` | 是 |
| 电视剧 | Series | `/series`，一张卡片代表一部电视剧 | 是，按系列数展示 |
| 图片 | Media | `content_type=image` | 是 |
| 音频 | Media | `content_type=audio` | 是 |

`单集`不作为一级分类。它是电视剧详情中的内容，也可作为“高级筛选 > 内容形态”入口。`纪录片`不作为互斥一级分类，它属于题材，可能同时是电影或电视剧。

### 2.2 电影识别

当前后端只有来源类型 `media_type` 和 MIME 内容类型，没有稳定的“电影”字段。第一阶段不做数据库迁移，按以下顺序识别：

1. `series_id IS NOT NULL`：单集。
2. 所属媒体库 `scrape_mode == tv`：待聚合单集，不进入电影。
3. `content_type == video` 且不属于电视剧：电影/独立视频，UI 显示为“电影”。
4. `genre` 包含纪录片时仍属于电影或电视剧，仅附加题材筛选。

后续若出现家庭视频、短视频等大量独立视频，再新增持久化 `content_kind`；不在本次首阶段提前迁移。

### 2.3 计数接口

新增轻量接口 `GET /api/media/facets`，一次返回受限内容过滤后的计数与筛选选项：

```json
{
  "all": 794,
  "movies": 412,
  "series": 67,
  "episodes": 208,
  "images": 78,
  "audio": 12,
  "genres": [{"value": "纪录片", "count": 96}],
  "countries": [],
  "years": [],
  "tags": []
}
```

`all`定义为可见的独立 Media 数量，不将 Series 再叠加，避免总数失真。主页混合视图顶部可另外显示“67 部电视剧”。

## 3. 里程碑一：主页框架与分类

### 输出

- 桌面客户端顶栏匹配设计稿，继续复用 `TopNav.svelte` 中的 Tauri 最小化、工作区最大化、关闭逻辑。
- 一级分类：全部、电影、电视剧、图片、音频。
- 快捷状态：未观看、观看中、收藏、网络媒体、本地缺失。
- 属性筛选：题材、国家/地区、年份、分辨率、评分、时长。
- 标签保留左侧树入口，筛选区支持多标签交集筛选。
- URL 参数完整持久化，刷新、分享与前进后退可恢复。

### 后端改动

- `backend/app/api/media.py`
  - 新增 `/media/facets`，使用聚合查询生成计数和筛选项。
  - 为单集筛选增加 `has_series=true|false`，避免前端猜测。
  - 保留现有 `content_type`、`genre`、`country`、`tag_ids`。
- `backend/app/schemas/media.py`
  - 新增 `MediaFacetsResponse` 及 facet item schema。
- `backend/app/api/series.py`
  - 列表增加题材、国家、年份、标签筛选仅在确有 Series 元数据时实施；首阶段至少保留库筛选与分页。

### 前端改动

- `frontend/src/routes/media/+page.svelte`
  - 把请求编排拆出，页面负责状态、URL、恢复和空/错/加载状态。
  - 新增 `contentSection`：`all | movie | tv | image | audio`。
- `frontend/src/lib/components/media/types.ts`
  - 扩展 `ViewMode` 为 `mixed | poster | timeline | list`。
  - 新增 `ContentSection`、完整 FilterState。
- `frontend/src/lib/components/media/FilterBar.svelte`
  - 拆为内容分类、快捷状态、属性筛选、标签筛选四层。
- `frontend/src/lib/components/layout/MediaSidebar.svelte`
  - 保留标签树和智能文件夹，增加一级内容入口。
- 新增 `frontend/src/lib/api/mediaFacets.ts`，隔离 facets 协议。

### 验证

- 分类切换不会同时显示 Series 与其单集。
- 多标签为交集语义，清除筛选会完整复位。
- URL 刷新后分类、筛选、排序不丢失。
- 受限媒体关闭时，计数和结果一致排除。
- `npm run check` 通过；后端新增聚合接口测试覆盖空库、电视剧库、受限库。

## 4. 里程碑二：混合媒体墙与四种视图

### 输出

- 混合视图：竖图 `2:3` 占一列；方图 `1:1` 占一列；横图占两列并使用 `4:3` 展示框。
- 海报墙：统一 `2:3`，用于最高信息密度浏览。
- 时间轴：按发行年份分组，卡片比例与混合视图一致。
- 列表：显示标题、库、类型、时长、分辨率、大小、评分、标签和进度。
- 密度滑杆持久化，不改变请求结果或滚动锚点身份。

### 组件设计

- 新增 `MixedMediaWall.svelte`：接受统一的 `DisplayItem` 联合类型。
- 保留并收敛 `PosterWall.svelte`、`SeriesWall.svelte`、`ListView.svelte`。
- `TimelineView.svelte` 不再简单嵌套旧 PosterWall，改为接收可复用的卡片渲染策略，确保横图规则一致。
- `UnifiedWall.svelte` 逐步被 `MixedMediaWall` 替代，迁移完成后删除。
- 新增 `MediaCard.svelte` 与 `SeriesCard.svelte`，集中处理徽标、进度、受限遮罩、缺失和网络状态。

### 分页策略

混合“全部”视图不能简单拼接两个独立分页后再排序。首阶段采用稳定、可解释的策略：

- Series 和独立 Media 分别请求。
- 前端按后端返回顺序做稳定合并，只承诺“各自顺序稳定”，不声称全局严格排序。
- 时间轴只对 Media 使用年份分组；电视剧在电视剧分类中单独浏览。
- 若未来必须全局严格排序，再新增后端统一 feed endpoint，不在前端伪造分页。

### 验证

- 横图宽度等于两张竖图加中间间距，混合视图与时间轴一致。
- 1280x720、1440x900、1920x1080 和最小 Tauri 窗口无横向溢出。
- 调整密度、切换视图、进入详情再返回，锚点和滚动位置正确。
- 500+ 卡片滚动无明显重排抖动，继续使用 `content-visibility`。

## 5. 里程碑三：图片查看器

### 路由与职责

新增 `/image/[id]`，不继续塞进视频播放器。媒体墙点击图片进入专用查看器；详情页仍负责元数据编辑。

### 首版功能

- 原图流式读取，支持 JPEG、PNG、WebP、GIF；浏览器原生不支持的 HEIC/AVIF 给出明确错误或后端转码预览。
- 适应窗口、原始尺寸、缩放、拖拽、左右旋转、重置。
- 同目录或同筛选结果的上一张/下一张导航。
- 底部缩略图带可折叠，支持键盘方向键。
- 图片信息：尺寸、文件大小、拍摄/修改时间、标签。
- 可选幻灯片，首版只提供固定间隔，不做复杂转场。

### 后端

- 复用 `/media/{id}/stream` 前先确认图片 Range/Content-Type 行为。
- 推荐新增 `/media/{id}/original`，仅服务图片原文件并执行资产路径、安全、软删除、受限检查。
- 新增相邻项 endpoint 或在进入查看器时传入当前结果 ID 快照；优先采用当前结果快照，避免新增高成本查询。

### 前端文件

- `frontend/src/routes/image/[id]/+page.svelte`
- `frontend/src/lib/components/image/ImageStage.svelte`
- `frontend/src/lib/components/image/ImageFilmstrip.svelte`
- `frontend/src/lib/stores/imageViewer.svelte.ts`

### 验证

- 大图不会一次性生成 base64；缩放和拖拽不改变页面布局。
- GIF 保持动画；透明 PNG 背景可辨识。
- 文件缺失、格式不支持、受限内容均有明确状态。

## 6. 里程碑四：音频播放器与本地歌词

### 路由与职责

新增 `/audio/[id]` 或在 `/player` 内按内容类型分派到独立 `AudioPlayer`。推荐独立路由，复用底层播放 store 和进度 API，避免视频控制器继续膨胀。

### 首版功能

- 封面、曲名、艺术家、专辑、年份、格式信息。
- 播放/暂停、跳转、音量、倍速、上一首/下一首。
- 当前筛选结果作为播放队列；循环、单曲循环、随机。
- 支持内嵌歌词文本和同名 `.lrc` 文件；时间轴歌词滚动与当前行高亮。
- 没有歌词时显示封面和简洁频谱/波形占位，不自动请求第三方歌词。

### 数据模型与迁移

里程碑四单独增加 Alembic 迁移：

- Media 增加可空字段：`artist`、`album`、`track_number`、`disc_number`。
- 歌词建议新建 `lyrics` 表：`media_id`、`source_type`、`language`、`format`、`content`、`file_path`、`is_synced`。
- 不把完整 LRC 塞入 `scrape_data`，避免业务字段和第三方抓取数据混用。
- 扫描器发现同目录同名 `.lrc` 时建立/更新记录；文件监听器处理新增、修改、删除。

### 后端文件

- 新增 `backend/app/models/lyrics.py`、`schemas/lyrics.py`、`api/lyrics.py`。
- 修改 `services/scanner.py`、`services/file_watcher.py`、`services/metadata.py`。
- 新增迁移 `018_add_audio_metadata_and_lyrics.py`。

### 前端文件

- `frontend/src/routes/audio/[id]/+page.svelte`
- `frontend/src/lib/components/audio/AudioPlayer.svelte`
- `frontend/src/lib/components/audio/LyricsPanel.svelte`
- `frontend/src/lib/components/audio/QueuePanel.svelte`
- `frontend/src/lib/utils/lrc.ts`

### 验证

- MP3、FLAC、M4A、WAV 基本播放；不支持格式明确报错。
- 无歌词、纯文本歌词、同步 LRC、格式损坏均有测试。
- 切歌、拖动、退出应用前的进度保存与现有视频一致。
- 歌词文件路径不得泄露到 API 响应。

## 7. 实施顺序与发布门槛

1. **M1：主页框架与分类**  
   输出：可用的新主页，不改变现有详情和播放器。  
   门槛：分类计数正确，旧功能无回归。

2. **M2：四种视图与比例卡片**  
   输出：设计稿中的混合媒体墙、海报墙、时间轴、列表。  
   门槛：视觉检查、滚动恢复和 500+ 项性能通过。

3. **M3：图片查看器**  
   输出：图片从“能打开”升级为完整浏览。  
   门槛：主流格式、错误状态、键盘导航通过。

4. **M4：音频与本地歌词**  
   输出：专用音频消费体验和 LRC 支持。  
   门槛：迁移可升级/降级，播放进度与歌词同步稳定。

每个里程碑单独提交，禁止将 M3/M4 的数据库变化混入 M1/M2。若时间有限，M1+M2 即可形成完整、可发布的主页改版。

## 9. 风险与回滚

- **分类计数不一致**：统一由 facets API 计算，不让前端根据当前页推算。
- **混合分页排序误导**：首版明确不做全局严格排序，必要时后续新增统一 feed。
- **旧数据 MIME 缺失**：继续使用后端扩展名兜底，测试旧库。
- **系列重复展示**：全部视图 Media 请求强制 `exclude_series=true`。
- **性能回退**：facets 聚合增加索引评估；卡片保留懒加载和 content visibility。
- **数据库迁移风险**：只在 M4 引入，迁移前备份 SQLite，提供 downgrade。
- **快速回滚**：M1/M2 保留旧组件至验收结束，通过功能开关或单提交 revert 恢复旧主页。
