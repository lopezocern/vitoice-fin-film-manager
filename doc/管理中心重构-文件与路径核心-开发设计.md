## 1. 结论

本次管理中心不重写媒体系统，也不把媒体页功能搬进管理页。采用**增量重构**：保留现有媒体、标签、回收站、批处理、扫描、刮削和任务能力，先建立独立的管理工作区壳层，再将“文件与路径”升级为默认入口和核心操作面。

核心闭环为：

`定位资源库/目录 -> 查看真实文件 -> 选择或拖入文件 -> 预览影响与冲突 -> 执行文件操作 -> 同步媒体记录 -> 查看任务与操作记录 -> 必要时进入问题中心`

首期覆盖视频资源库、目录、视频文件和已有网络媒体记录。网络媒体没有实体文件，或来自“本地文件已删除但网络播放源仍保留”的媒体记录，必须在文件与路径工作区中拥有独立、可治理的来源视图。图片、音频及任意系统文件管理不在首期扩展范围内，避免在媒体类型模型尚未完成前扩大扫描器和元数据管线的风险。

## 2. 产品边界

### 2.1 媒体页

媒体页服务“观看”：继续观看、最近播放、发现、筛选、详情、播放和返回现场。它只暴露低风险快捷动作，不承担批量文件治理。

### 2.2 管理页

管理页服务“治理”：资源定位、文件导入和整理、元数据修复、标签治理、问题诊断、批量操作、任务观察和审计。

### 2.3 明确不做

- 不在管理页复制“继续观看”“猜你喜欢”等消费内容。
- 不把管理中心做成可访问整个磁盘的通用资源管理器，只允许操作已登记资源库根目录内的目录和媒体文件。
- 不在首期实现图片查看器、音频播放器、歌词、任意文档管理。
- 不为网络媒体伪造磁盘路径或虚拟文件夹；它仍以 Media 与 MediaUrl 数据关系存在。
- 不以标题、文件名、电视剧类型或刮削结果猜测成人内容。
- 不替换现有播放、进度、系列聚合和刮削主链路。

## 4. 方案选择

### 4.1 采用：增量工作区重构

新增管理工作区壳层和文件操作服务，旧视图逐个挂入新导航。每个阶段可独立发布和回滚，现有 `/manage?tab=media|tags|recycle` 在迁移期继续可用。

### 4.2 不采用：只换管理页外观

仅修改 Svelte 布局无法解决拖拽导入、删除语义、操作审计、并发竞争和大目录性能，最终会形成“看起来能操作、实际不可靠”的界面。

### 4.3 不采用：重写扫描器和媒体模型

现有扫描、系列聚合、刮削、播放和回收站已经形成依赖关系。整体重写风险高，且与当前页面目标无关。首期只在文件变更入口增加协调层。

## 5. 信息架构与路由

管理中心使用稳定的 `section` 路由状态：

| 页面 | URL | 职责 |
|---|---|---|
| 文件与路径 | `/manage?section=files` | 默认页，真实目录和文件操作 |
| 资产工作台 | `/manage?section=overview` | 总量、状态、最近任务和快捷入口 |
| 问题中心 | `/manage?section=issues` | 缺失、冲突、待刮削、路径异常、失败任务 |
| 媒体资产 | `/manage?section=assets` | 基于媒体记录的批量编辑与治理 |
| 元数据与刮削 | `/manage?section=metadata` | 匹配、字段差异、来源和批量刮削 |
| 标签治理 | `/manage?section=tags` | 标签类型、层级、合并、删除和覆盖范围 |
| 回收站 | `/manage?section=recycle` | 软删除记录、恢复和永久清理 |
| 任务队列 | `/manage?section=tasks` | 运行中、等待、完成和失败任务 |
| 操作记录 | `/manage?section=history` | 文件与数据变更审计 |
| 资源库状态 | `/manage?section=libraries` | 根路径、在线状态、监听和扫描配置 |

兼容规则：旧 `?tab=media` 映射到 `section=assets`，`?tab=tags` 映射到 `section=tags`，`?tab=recycle` 映射到 `section=recycle`。迁移期不主动删除旧参数支持。

“文件与路径”内部可恢复状态写入 URL：

```text
/manage?section=files&source=local&library=3&path=2024%2F国产剧&view=list&sort=name.asc&q=&status=
```

选中项、面板宽度和滚动锚点属于临时 UI 状态，不写入 URL；列表/平铺偏好与树/检查器宽度写入 `localStorage`。

## 6. “文件与路径”交互规格

### 6.1 三栏结构

- 左栏：资源库与懒加载目录树，可折叠、调整宽度。
- 中栏：面包屑、主工具栏、突出显示的单文件导入区、列表/平铺内容区、状态栏。
- 右栏：单选检查器；多选时显示选择摘要、影响范围和批量动作，可折叠、调整宽度。

窗口较窄时先收起检查器，再收起目录树；中栏最小宽度不得低于 560px。移动端不作为首期正式支持目标，但最小 Tauri 窗口不能产生不可操作的横向溢出。

### 6.2 来源视图

文件与路径工作区提供三个来源视图：

| 来源视图 | 数据口径 | 主要操作 |
|---|---|---|
| 本地文件 | `file_path` 存在且本地文件可访问；包含 `LOCAL` 与 `BOTH` | 导入、新建目录、重命名、移动、扫描、删除、播放 |
| 网络媒体 | 至少存在一个 `MediaUrl.url_role=source`；包含 `NETWORK`、`BOTH` 及本地缺失但网络源仍存在的记录 | 播放、增加/编辑/删除来源、检测来源、设置默认来源、关联本地文件 |
| 本地缺失 | `file_missing=true` 或 `media_type=OFFLINE` | 网络播放（若有源）、重新关联本地文件、查找路径、移除记录 |

三个计数允许重叠，不相加为媒体总数。例如 `BOTH` 同时出现在本地文件和网络媒体视图；本地文件删除后仍有网络源的记录同时出现在网络媒体和本地缺失视图。界面必须显示当前视图口径，禁止用互斥分类误导用户。

网络媒体视图继续按资源库筛选，但不显示实体目录层级，也不显示新建文件夹、导入和扫描目录命令。网络条目的“路径”区域改为来源摘要与本地关联状态，检查器展示来源列表、平台、可用性、上次检测时间和本地关联。

### 6.3 筛选、搜索与排序

- 搜索覆盖名称、真实路径、来源平台和网络地址的可显示摘要；默认只作用于当前来源视图和资源库。
- 筛选至少包含：对象（文件夹/媒体）、状态（可播放/异常/已刮削/待刮削）、来源（有本地文件/有网络源）、受限内容和资源库。
- 已启用条件以可移除标签显示在工具栏下方，筛选数量显示在筛选按钮上。
- 排序包含：名称、最近修改/来源更新时间、文件大小、最近入库、状态；网络媒体不支持文件大小时以空值排在末尾。
- 筛选、搜索、排序和来源视图进入 URL，切换列表/平铺或进入详情后返回时完整恢复。
- 来源视图切换后自动清除不适用的目录选择，但保留可共享的搜索词和资源库筛选。

### 6.4 列表与平铺

- 列表默认展示：名称、类型/分辨率、大小、修改时间、入库/刮削状态。
- 平铺展示：文件夹图标或媒体封面、名称、大小和状态；封面不存在时使用类型占位，不用视频随机截图冒充海报。
- 目录始终排在文件前；之后按用户选择的名称、修改时间、大小或状态排序。
- 中栏内部连续滚动，不显示分页器。
- 接口每次加载 100 项，滚动接近底部继续取下一游标；列表采用虚拟化，DOM 常驻目标不超过 200 行/卡片。
- 切换列表/平铺时保持当前目录、筛选、选中项和滚动锚点。

### 6.5 选择和快捷操作

- 单击选中并刷新检查器；双击文件夹进入，双击已建立媒体记录的项目复用现有详情页。
- 普通媒体与单集统一使用现有 `/detail/[media_id]`；系列使用现有 `/series/[series_id]`，不在管理中心另建第二套媒体详情组件。
- 右侧检查器将“查看媒体详情”作为首要动作；纯文件、空文件夹和仍在等待索引的导入项没有 `media_id`，因此不显示该动作。
- 进入详情前保存当前 `section=files`、来源、目录、搜索、筛选、排序、列表/平铺、选中项与滚动锚点；从详情返回时恢复原现场，不重新定位到资源库根目录。
- 复选框用于多选，`Shift` 连选，`Ctrl`/`Cmd` 切换选择。
- 右键菜单提供：打开详情、播放、重命名、移动、重新扫描、定位文件、从库移除、删除本地文件。
- 工具栏只放高频命令：导入单个文件、新建文件夹、批量导入、扫描当前目录、列表/平铺切换。
- 长任务确认后进入任务队列；短操作完成后局部刷新，不整页重载。

### 6.6 单文件拖拽导入

桌面端通过 Tauri 文件对话框或拖放事件获取**真实绝对路径**。浏览器开发模式若无法取得真实路径，只显示“选择文件”，不使用浏览器上传伪装本地导入。

导入流程：

1. 用户将一个文件拖入导入区，或点击选择文件。
2. 前端确认当前目标资源库和目录，调用预览接口。
3. 预览显示源文件、目标路径、大小、预计耗时、冲突和磁盘空间。
4. 默认策略为“复制到当前目录”；“移动到当前目录”必须显式选择。
5. 源文件已位于当前资源库内时，可选择“仅建立索引”。资源库外文件不能仅引用。
6. 执行后先完成磁盘操作，再建立/更新媒体记录，最后按需触发元数据、缩略图和刮削任务。

首期冲突策略只支持 `keep_both`（自动后缀）和 `skip`。覆盖已有文件延后实现，避免首期引入不可恢复的数据覆盖。

### 6.7 网络来源治理

- 一个媒体可包含多个 `source` URL 和多个 `reference` URL；只有 `source` 参与可播放状态和默认来源选择。
- 来源操作包括新增、编辑显示名、检测、设为默认、停用/恢复和删除。删除最后一个网络播放源后，若无本地文件，媒体进入“仅剩记录”状态，不自动永久删除。
- `BOTH` 删除本地文件后转换为可网络播放状态，保留标题、标签、封面、播放进度、系列关系和来源。
- 重新关联本地文件只更新本地路径与文件状态，不新建第二条媒体记录；媒体 ID、播放进度和标签保持不变。
- 来源失效由显式检测结果产生，不因一次播放超时立即永久标记；记录最近成功、最近失败和连续失败次数。
- 管理界面显示完整来源域名和平台，但对查询参数中的 token、签名和用户信息进行脱敏。

### 6.8 删除语义

界面不得只写一个含糊的“删除”。提供三个明确动作：

| 动作 | 文件 | 媒体记录 | 可恢复性 |
|---|---|---|---|
| 从 vitoice 移除 | 保留 | 进入现有回收站 | 可恢复记录 |
| 删除本地文件 | 永久删除 | 进入回收站并标记本地文件缺失；网络源保留 | 只能恢复记录，不能恢复文件 |
| 递归删除文件夹 | 永久删除目录及内容 | 受影响记录进入回收站/缺失状态 | 不可恢复文件 |

物理删除必须展示文件数量、总大小、受影响媒体记录和受限内容数量，并要求二次确认。首期不宣称使用操作系统回收站，因为当前工程没有可验证的跨平台恢复能力。

## 8. 后端模块设计

新增服务边界：

```text
backend/app/api/file_entries.py
backend/app/api/file_operations.py
backend/app/api/operation_history.py
backend/app/schemas/file_operation.py
backend/app/models/file_operation.py
backend/app/services/path_policy.py
backend/app/services/file_mutation.py
backend/app/services/mutation_coordinator.py
backend/app/services/operation_audit.py
```

职责：

- `path_policy`：资源库根路径、相对路径、符号链接、保留名、扩展名、源路径和目标路径校验。
- `mutation_coordinator`：按资源库加锁、生成幂等键、登记 watcher 抑制范围、统一触发重扫。
- `file_mutation`：预览并执行创建、导入、重命名、移动、移除和物理删除。
- `operation_audit`：保存操作、逐项结果、前后路径、错误码和关联任务。
- API 层只做 schema 校验、权限/设置判断和响应转换，不直接调用 `shutil`。

现有目录和文件移动端点在过渡期保留，但内部改为调用 `file_mutation`，避免形成两套磁盘操作逻辑。

## 9. 数据模型

新增 Alembic 迁移，不能只依赖 `create_all()` 或启动时自动补列。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID/String(36) PK | 操作 ID |
| `kind` | String(32) | import/create_dir/rename/move/remove/delete/scan |

| `task_id` | FK nullable | 长任务关联 |

### 9.2 `file_operation_items`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Integer PK | 明细 ID |

## 11. 文件系统安全与一致性

### 11.1 路径安全

- API 对库内目标只接受 `library_id + rel_path`，不接受前端传入目标绝对路径。
- 每次操作都对 `Path.resolve()` 后的目标执行 `relative_to(root)` 校验。
- 源和目标均拒绝符号链接、`..`、隐藏系统目录、Windows 保留名和非法字符。
- 禁止删除、重命名或移动资源库根目录。
- 跨库操作同时校验两个根目录，按 library ID 排序加锁以避免死锁。
- CORS 继续只允许可信本地前端来源；文件操作 API 不增加宽泛来源。

### 11.2 操作顺序

1. 加锁并复核 revision。
2. 创建 `file_operation` 与明细。
3. 注册 watcher 抑制路径和操作 ID。
4. 执行磁盘变更。
5. 磁盘成功后更新数据库路径、库 ID、缺失/删除状态。
6. 写入逐项结果并提交审计。
7. 释放抑制，按影响范围触发定向扫描或系列聚合。

数据库更新失败时先尝试回滚物理变更。回滚失败则标记 `RECONCILIATION_REQUIRED`，保留完整操作记录并排入定向扫描，不能向用户返回普通成功。

### 11.3 复制与跨盘移动

- 先复制到目标目录临时文件 `.vitoice-import-<uuid>.part`。
- 完成后校验大小和 64KB 前缀哈希，再原子重命名为最终文件名。
- `move` 在校验目标成功后才删除源文件。
- 取消任务时删除临时文件；若源文件已经删除则不允许简单标记取消，必须进入回滚/部分完成状态。

### 11.4 watcher 与扫描协调

现状中 watcher 会即时更新记录并延迟触发全库扫描，应用内部移动也会产生同样事件。新增：

- `MutationCoordinator` 维护规范化路径、操作 ID 和短期 TTL 的抑制登记。
- watcher 收到内部操作事件时只归并状态，不重复创建媒体记录或排入第二个扫描任务。
- `TaskManager.enqueue_unique(dedupe_key)` 保证同一资源库同时最多一个 scan；watcher 和 HTTP 扫描入口都调用它。
- 同一资源库的文件变更任务串行；不同资源库可并发。跨库操作同时占用两个库锁。
- 数据库增加活动媒体路径唯一约束或等价的规范化路径冲突检查，作为最后一道重复记录防线。

## 12. 受限内容规则

唯一权威来源是资源库 `MediaLibrary.is_restricted`，后续若新增资产级显式字段，再以显式字段并集判断。以下做法禁止：

- 根据标题、文件名、演员、类型或电视剧身份猜测。
- 因为刮削模式为 `tv`、`movie` 或刮削失败而标记受限。
- 因海报缺失或系列聚合异常而标记受限。

行为规则：

- `show_restricted=false`：管理导航、目录树、列表、计数和搜索均排除受限资源库及其资产。
- `show_restricted=true`：可以管理，库、文件、预览和确认框显示“受限内容”标识。
- `mask_restricted=true`：列表和平铺中的海报应用遮罩；文件名、路径和治理状态仍可读，保证可管理。
- 操作预览必须返回 `restricted_count`，批量操作不会因遮罩而漏算。

## 13. 任务和操作记录分工

- 任务回答“现在执行到哪一步”：可取消、短期保留、显示进度和当前文件。
- 操作记录回答“谁在什么时候改变了什么”：长期保留、不可编辑、可查看逐项结果。
- 当前任务系统只有取消能力，首期界面不得显示“暂停/继续”。设计稿中的“暂停全部”在实现前删除或改为“取消等待中任务”。
- 已完成任务被清理后，关联操作记录仍可查看结果摘要。

12. 电视剧不会因类型或标题被误判为受限内容；受限内容开关、遮罩、计数和操作预览一致。
13. 旧媒体资产、标签、回收站、扫描、刮削和跨库移动功能无回归。

## 17. 回滚与兼容策略

- 每个阶段使用独立功能开关：`manage_workspace_v2`、`file_explorer_mutations`、`desktop_file_import`。
- 新工作区异常时可关闭 `manage_workspace_v2`，恢复旧 `/manage?tab=` 页面。
- 新操作 API 上线后，旧目录/移动端点至少保留一个发布周期，并内部委托同一服务。
- 数据库迁移只新增表、索引和可空关联字段；关闭功能不要求回滚数据。
- 禁止自动执行物理数据迁移或批量整理。首次启用只读取现有资源库。

## 18. 实施前置决定

以下决定已在本文固定，开发时不再临时猜测：

- 文件与路径是默认管理页。
- 首期范围是目录和视频文件，不提前开发图片/音频。
- 网络媒体和本地缺失媒体属于首期管理范围，复用现有 Media/MediaUrl 模型。
- 来源视图允许重叠，不用互斥分类重写媒体来源状态。
- 单文件导入默认复制；移动需要显式选择；覆盖文件首期不做。
- 文件操作由后端统一执行，Tauri 只负责取得用户选择的源路径。
- 删除分级，不把软删除和物理删除混成一个按钮。
- 管理页和媒体页保持独立信息架构与状态。
- 受限内容只来自显式资源库标记，不使用内容猜测。
- 先完成安全基线和只读浏览，再逐步开放写操作。

### 20.6 媒体页侧边栏交互修复

- 根因一（快照劫持）：媒体页 `loadMedia` 顶部检测 `mediaScroll.savedItems` 会直接走快照恢复并 return。用户从详情/播放返回后快照残留，再点侧边栏切换视图时永远加载旧快照，表现为"点击没反应"。修复：导航变化 effect（`lastNavKey` 变化）时清除 `savedItems/savedSeries/anchorId/anchorOffset` 并复位 `snapshotGuardUntil`。
- 根因二（观看中心 tab 吞导航）：媒体页 `pageMode==='center'`（观看中心）时只渲染 WatchCenter，不消费 `navigation.current`，侧边栏点击只更新 store 不换内容。修复：`navigation` store 增加 `navigateCount`（每次 `set()` 自增），媒体页追踪该计数，用户点击侧边栏（计数变化）时自动把 `pageMode` 切到 `'library'`（媒体库），随后导航节点变化触发对应加载。

### 20.9 媒体资产视图默认库过滤

### 20.10 目录树点击不切换库修复

- 问题：媒体管理页左侧"资源库与目录"树点击库或文件夹后，右侧未展示对应媒体。
- 根因：`FileExplorerView` 的 URL 同步 effect 只更新 `currentDir`（dir 参数），**未同步 `selectedLibraryId`**（lib 参数）——点击树节点 goto 到 `?lib=X&dir=Y` 后，`loadContent` 仍用旧的 `selectedLibraryId` 加载，导致右侧显示错误库/旧库内容。

### 20.13 目录树点击媒体未选中修复（两处）

### 20.16 方案 A：文件浏览并入媒体资产视图（2026-08-15）
