# 媒体数据源统一管理 — 实施方案（细化版）

> 状态：待确认（未实施）
> 日期：2026-08-10
> 关联：解决三类刮削源（电影/电视剧/AV）的配置化与回退问题；与「成人控制项统一管理」方案合并为同一功能

---

## 1. 目标

将三类刮削源（电影 TMDB、电视剧 TMDB、AV 三源）统一为**可可视化配置的有序回退链**：

| 现状问题 | 本方案解决 |
|---|---|
| 电影/电视剧：TMDB 单源无回退，挂了/被墙即全挂 | 支持配置镜像/备用源，按优先级自动回退 |
| AV：三源回退但地址硬编码（`av_scraper.py` 模块常量），域名被封只能改代码 | 源地址全部进 settings 表可视化配置 |
| 前端漏配 `tmdb_image_base` | 数据源管理器补齐图片地址配置 |
| 配置机制不统一（TMDB 读 DB、AV 读 env 常量） | 统一为 `scrape_sources` JSON 配置 + 加载器 |

**范围边界**：仅做"刮削数据源"的配置化与回退。不含：播放抓取（javgg，另行立项）、网络媒体导入、显示策略（已存在于 content 分区）。

## 2.5 隔离设计（硬性约束：正常内容 与 成人内容 严格隔离）

用户确认方案时明确要求：**隔离好正常内容和成人内容**。以下隔离边界在实施中强制执行：

| 层面 | 隔离规则 |
|---|---|
| **结构隔离** | `scrape_sources` 的 movie/tv 组与 av 组是独立数组；加载器 `load_scrape_sources(kind)` 只读对应组，**绝不跨类读取**。AV 源（javbus 等）永远不会出现在电影/电视剧回退链中，反之亦然 |
| **路由隔离** | `scrape_media` 按 `ScrapeMode` 路由（已有）：AV 库只走 AV 源链，MOVIE/TV 库只走 tmdb 源链。回退循环内**禁止** av 组源参与 movie/tv 尝试、禁止 tmdb 组源参与 av 尝试（`kind` 字段即解析器类型，天然隔离） |
| **UI 隔离** | SourceManager 三组卡片分区渲染；AV 组加"成人"警示标识（颜色/角标），与影视组视觉区分 |
| **显示隔离** | 数据源配置与显示策略解耦：`show_restricted`/`mask_restricted`（content 分区）继续独立生效；开启/关闭受限显示不影响任何源配置 |
| **测试隔离** | `POST /settings/test-source` 请求体带 `kind`，服务端校验该源确属该 kind 组才执行测试 |
| **持久化隔离** | 存储层（Media/MediaLibrary）的 `is_restricted` 标记与刮削源配置互不影响；AV 库刮削只写 AV 元数据，不触碰正常媒体 |



## 2. 设计决策（已核实代码后确定）

### D1 配置存储：单个 JSON 键 `scrape_sources`

- `settings` 表新增一行：`key='scrape_sources'`，`type='json'`（`SettingType.JSON` 原生存在），`category='scrape'`，`value=<默认 JSON>`
- 理由：单键内聚、前端易做列表编辑、回退框架天然支持任意数量源；`value` 列为 Text 可存 JSON 字符串
- 备选（多键：tmdb_backup_base_url 等）否决：回退链变长后键爆炸、前端碎片化

### D2 回退链解析规则（向后兼容）

```
scrape_sources[kind] 非空且含启用源
  → 回退链 = 该列表（按数组顺序尝试）
scrape_sources[kind] 为空 / 不存在
  → movie/tv：默认链 = [现有 tmdb_* 键配置]（行为与今天完全一致）
  → av：默认链 = [javbus, javdb, javlibrary, DMM海报]（现有硬编码默认值）
```

- **主源兼容**：movie/tv 现有 `tmdb_api_key/base_url/image_base/language` 4 键**继续生效**（作为默认源）；JSON 里新增的 tmdb 类型源若 `api_key` 留空，**继承全局 tmdb_api_key**（镜像场景友好）
- **AV 完全接管**：`scrape_sources.av` 非空时完全替代默认三源（满足"域名被封改配置"需求）；为空时行为不变

### D3 源配置 JSON Schema

```json
{
  "movie": [
    {
      "name": "TMDB 镜像A",
      "kind": "tmdb",
      "base_url": "https://api.themoviedb.org/3",
      "image_base": "https://image.tmdb.org/t/p/w500",
      "api_key": "",
      "language": "zh-CN",
      "timeout": 30,
      "enabled": true
    }
  ],
  "tv": [],
  "av": [
    { "name": "JavBus",   "kind": "html", "base_url": "https://www.javbus.com",  "timeout": 30, "enabled": true },
    { "name": "JavDB",    "kind": "html", "base_url": "https://javdb.com",       "timeout": 30, "enabled": true },
    { "name": "JavLibrary","kind": "html","base_url": "https://www.javlibrary.com","timeout": 30, "enabled": true }
  ]
}
```

- `kind`：`tmdb`（走 `_tmdb_search/detail/credits` API 逻辑）| `html`（走 av_scraper 的 bs4 解析）
- 数组顺序 = 优先级（前端上移/下移调整）
- `enabled=false` 的源跳过（保留配置但临时停用）

### D4 归属调整（与成人控制项方案合并后的职责划分）

| 分区 | 承载内容 |
|---|---|
| **刮削（scrape）** | 数据源管理器：movie / tv / av 三组源列表（含 AV 源地址）——本方案 |
| **内容管理（content）** | 仅显示策略：show_restricted / mask_restricted（已有）+ 预留 network_allow_adult（后续 javgg 抓取立项时加） |

> 调整说明：上轮将 AV 源地址规划在 content 分区，本轮统一后改为放 scrape 分区（AV 源本质是刮削数据源，与影视源同构）。显示策略与数据源解耦，关闭 show_restricted 不影响源地址配置。

## 4. 后端改造明细

### 4.1 `backend/app/services/scraper.py`（核心）

**新增数据结构与加载器：**

```python
@dataclass
class ScrapeSource:
    name: str
    kind: str                    # "tmdb" | "html"
    base_url: str = ""
    image_base: str = ""
    api_key: str = ""
    language: str = ""
    timeout: int = 30
    enabled: bool = True

_KIND_ORDER = ("movie", "tv", "av")

def parse_scrape_sources(raw_json: str | None, kind: str) -> list[ScrapeSource]:
    """解析 settings['scrape_sources'] 中某 kind 的源列表；畸形 JSON 静默回退 []"""

async def load_scrape_sources(db_or_session, kind: str) -> list[ScrapeSource]:
    """读 settings 表 → 解析 → 返回启用源列表。
    kind=movie/tv 且列表空 → 由现有 tmdb_* 键构造单源默认链；
    kind=av 且列表空 → 由 av_scraper 默认常量构造三源链。"""
```

**`scrape_media` 改造（MOVIE/TV 分支）：**

现有结构：单源 `_tmdb_search → _tmdb_detail → _tmdb_credits → _download_poster`，改动为：

```
sources = await load_scrape_sources(db, kind)     # 含默认链
last_err = None
for src in sources:
    if not src.enabled: continue
    cfg = _source_to_tmdb_config(src)             # tmdb 源；api_key 空继承全局
    try:
        hit = await _tmdb_search(client, cfg, kind, query, year)
        if not hit and year: hit = await _tmdb_search(client, cfg, kind, query, None)
        if not hit: continue                      # 无结果 → 切下源
        # 命中后沿用现有 detail/credits/poster 逻辑（把 cfg 换成 src 的 cfg）
        ...
        break                                     # 成功跳出
    except (httpx.HTTPError, TimeoutError) as e:
        last_err = e; continue                    # 网络失败 → 切下源
if not hit:
    return ScrapeResult(matched=False, message=f"所有数据源均未找到匹配：{query}（{last_err}）")
```

- 失败判定：网络错误（切源）+ 无搜索结果（切源）两类
- `query_override`（AI rescrape）路径保持，仅包装在循环内
- 源命中后其余逻辑（Series 聚合、标签同步）**零改动**——它们消费的是 `new_title/detail/scrape_data`，与源无关
- TV 的 Series 聚合依赖 `tmdb_id`：非 TMDB 源缺失 tmdb_id 时，现有 `series_title` 标题分组兜底已存在（`scrape_media` 内 `if not series and media.series_title` 分支），兼容

**新增源测试函数：**

```python
async def test_scrape_source(src: ScrapeSource, kind: str) -> tuple[bool, str]:
    """仿 test_tmdb_connection：tmdb 源 → GET {base}/search/movie?query=matrix；
    html 源 → GET {base} 首页/搜索页探测 200。返回 (ok, message)，不抛异常。"""
```

## 6. 兼容性与风险

| 风险 | 评估 | 缓解 |
|---|---|---|
| 现有用户迁移 | 低 | `scrape_sources` 默认空数组 → 全走旧逻辑；`resolve_tmdb_config` 未删 |
| av_scraper 参数化回归 | 中 | 默认常量保留为兜底；用番号样本（如 DASS-699）跑一次 AV 刮削回归 |
| 回退循环拖慢批量刮削 | 中 | 每源 timeout 默认 30s；串行循环 + 源数量少（默认 1-3）；失败快速跳过（无结果/4xx 不等待） |
| 非 TMDB 源缺 tmdb_id 影响 Series | 低 | 现有 `series_title` 标题分组兜底分支已存在 |
| JSON 配置损坏 | 低 | `parse_scrape_sources` 畸形 JSON 静默回退空列表；PUT 端点服务端校验 |
| 前端 svelte-check | — | 新组件按项目现有模式写，跑 `svelte-check` 门禁 0 error |
