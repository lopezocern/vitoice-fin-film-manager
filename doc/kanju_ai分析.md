我觉得 vitoice 不需要照搬 kanju.ai 的“在线影视站”，而应该把它改造成更适合本地媒体管理的闭环：

`打开 vitoice → 看到最值得继续的内容 → 搜索或浏览 → 一键播放 → 自动记住现场 → 回来无感续播`

你们其实已经具备搜索、播放进度、继续观看、历史数据和跨播放源进度这些基础能力。现在缺的主要不是后端功能，而是把它们组织成一条明显、顺滑的主线。

**我最推荐的方向：媒体首页升级为“观看中心”**

当前媒体页偏向“浏览整个库”，用户进来以后仍然需要筛选、找海报、进详情。建议首页内容按行动优先级排列：

1. `继续观看`
   放在第一屏最上方，只显示真正中断的内容。卡片突出剩余时间、播放进度和“继续播放”，点击卡片主体直接续播，不再先进详情。

2. `最近添加`
   展示新入库内容，解决“刚导入的片去哪了”。

3. `最近播放`
   包含已经看完和刚播放过的内容，承担历史回溯。

4. `为你整理`
   暂时不用上复杂 AI，可以基于现有元数据生成：
   - 同导演
   - 同演员
   - 同系列
   - 同类型
   - 同标签
   - 尚未观看的高评分影片

5. `媒体库`
   原来的完整海报墙、筛选和排序继续保留，但从第一核心区域下移。

这样不会把首页做成流媒体广告页，依然符合 vitoice 安静、工具化的定位。

**搜索应该从“标题匹配”升级成“行动入口”**

现在全局搜索主要匹配标题和文件名。第一阶段不需要直接上大模型，先做结构化搜索就能明显提升体验：

- 搜标题、文件名、演员、导演、标签、类型、年份、库
- 输入“宫崎骏”“2020 年以后未看的科幻片”“两个小时以内”
- 结果按“最可能想播放”排序，而不是仅按更新时间
- 每条结果直接提供播放、查看详情、定位文件三个动作
- 搜索结果保留最近查询
- 空状态显示最近搜索和常用筛选，不放功能介绍文案

AI 更适合放在第二阶段：把自然语言翻译成已有筛选条件。它不应该替代媒体检索，只负责理解表达。

**播放链路需要真正闭环**

建议把行为规则统一下来：

- 未播放：按钮显示“播放”
- 已播放未结束：显示“继续播放 · 38:21”
- 接近片尾：自动标记已看
- 播放完：推荐下一集或返回详情
- 多播放源：默认选择上次使用的源，并共享主进度
- 播放失败：自动尝试可用网络源，同时明确告诉用户切换结果
- 返回：回到原列表位置、原筛选条件和原滚动位置
- 系列内容：优先续播上次一集，而不是重新打开系列首页

你刚刚遇到的“返回列表跳回顶部”，本质上正是这个闭环被打断了。它不是小交互问题，而是核心观看路径的一部分。

**详情页的角色也要调整**

详情页不应该成为播放前必须经过的一道门。它更适合承担“了解和管理”：

- 海报墙单击：进入详情
- 海报悬停或快捷按钮：立即播放
- 继续观看区域单击：直接续播
- 右键菜单：播放、详情、定位文件、编辑信息
- 详情页主按钮根据状态变成“播放”或“继续播放”
- 详情页明确展示上次播放时间、进度、播放源和文件状态

这样既照顾只想看片的人，也保留 vitoice 强大的管理能力。

**可以借鉴 kanju.ai 的其他部分**

值得借鉴：

- 搜索框成为全局高频入口，`Ctrl K` 保留
- 最近搜索形成“会话历史”，但不必做成聊天侧栏
- 继续观看比热门推荐优先
- 手机、TV 和桌面共享进度的思路
- 搜索结果直接播放，减少无意义页面跳转
- 更新日历可以转换为“新增媒体时间线”或“剧集更新”

不值得借鉴：

- 首页堆大量推荐栏目
- 虚构热度数字
- 用词元包装普通搜索
- 自动播放预告或动态大背景
- 把所有交互都做成聊天
- 在线片源聚合与来源不透明的播放线路

**建议分三期做**

第一期最有价值，也最稳：

- 首页增加“继续观看”和“最近播放”
- 搜索结果增加直接播放
- 所有入口统一续播规则
- 修复返回时的筛选、页码、视图和滚动恢复
- 统一已看、未看、播放中三种状态

第二期：

- 搜索扩展到演员、导演、标签、年份和类型
- 最近搜索与组合筛选
- 系列自动续播下一集
- 多播放源记忆与故障切换

第三期：

- 自然语言解析成结构化筛选
- 基于本地元数据生成片单
- 可选的跨设备历史与进度同步
- “今晚看什么”之类的轻量探索模式

我建议我们先做第一期，尤其是把媒体首页重构为“继续观看 + 最近播放 + 媒体库”三层结构。这会让用户第一眼就感受到产品从“文件展示器”变成了真正的个人观看中心。
