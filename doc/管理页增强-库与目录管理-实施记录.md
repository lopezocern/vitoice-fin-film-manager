| 能力 | 后端 | 前端入口 | 结论 |
|---|---|---|---|
| 目录树导航 | `GET /libraries/{id}/tree` ✅ | **无** | `DirectoryTree` 组件还在，但没人挂载 |
| 新建/重命名/删除目录 | `POST/PUT/DELETE /libraries/{id}/directories` ✅ | **无** | 只有已删除的 `FileExplorerView` 用过 |
| 移动到目录 | `PUT /libraries/{id}/files/move` ✅ | **无** | 同上 |

结论：**不是功能不全，是入口丢了。** 本轮全部补回。

## 1. 文件夹层级（核心需求）

### 1.1 目录树回归侧边栏

`ManageSidebar` 在 `section=assets` 时挂载 `DirectoryTree`（该组件本就按 assets 写好了 URL 约定）：

```svelte
{#if manageSection === 'assets'}
  <div class="tree-host">
    {#key folderTree.revision}
      <DirectoryTree libraries={librariesStore.libraries} {collapsed} />
    {/key}
  </div>
{/if}
```

点目录 → 写 URL `?section=assets&lib=5&dir=A` → `AssetsWorkspace` 的 `parseMediaQuery` 读到
`lib` / `dir` → `buildMediaQuery` 产出 `library_id` + `dir` → 列表按目录过滤。

**实测**：`/manage?section=assets&lib=5&dir=A` 显示 12 项，与 `GET /api/media?library_id=5&dir=A`
的 `total=12` 完全一致。

### 1.2 目录操作条（新组件 `AssetsFolderBar.svelte`）

面包屑（库名 › 子目录，每一段可点）+ 四个操作：

| 操作 | 接口 | 说明 |
|---|---|---|
| ← 上级 | — | 导航到父目录 |
| ＋ 新建文件夹 | `POST /directories` | 内联输入，Enter 提交 / Esc 取消 |
| 重命名 | `PUT /directories/rename` | 成功后跳到新路径（后端会同步更新媒体 `file_path`） |
| 删除目录 | `DELETE /directories?recursive=` | 非空目录先返回 400，前端升级为「递归删除」二次确认 |

安全边界全在后端（不许越出库根、目录名白名单、不许删库根）；前端只负责把错误原文展示出来，
不自己猜原因。

### 1.3 移动到目录（批处理栏）

`PUT /libraries/{id}/files/move`，支持同库/跨库、同名自动加后缀，返回逐条 `errors[{media_id,reason}]`。
UI 在批处理栏给一个「目标子目录」输入 + 「移到目录」按钮，结果用第一条错误文案提示。

### 1.4 目录树变更后刷新

`DirectoryTree` 把展开状态与子节点缓存在组件内部。目录被增删改名后缓存会过期。
新建了 `lib/stores/folderTree.svelte.ts`（一个自增 `revision`），
操作成功后 `folderTree.bump()`，侧边栏用 `{#key}` 重新挂载——比给组件加"强制刷新"接口侵入性更小。

| 问题 | 处理 |
|---|---|
| 批处理只报"失败 N 项"，用户无从下手 | toast 追加第一条失败明细 `（#id：原因）` |

## 6. 跨页全选（已完成）

### 问题

批量操作原本只能选「当前页」。治理 729 条的 AZV 要翻 15 页逐页勾选，实际没人会这么做。
但"全选筛选结果"不能靠前端逐页拉：一页 200 条约 800KB 的完整对象，874 条 3.4MB，上万条几十 MB。

### 后端：`GET /media?ids_only=true`

不改动既有过滤逻辑，只在算出 `total` 之后插一段短路分支：

```python
if ids_only:
    if total > MAX_IDS_ONLY:      # 20000
        raise HTTPException(413, "匹配 N 项，超过单次全选上限…请先增加筛选条件")
    sub = query.subquery()        # 复用上面的过滤子查询（与 count 同源）
    ids = await db.execute(select(sub.c.id))
    return MediaListResponse(items=[], total=total, ids=[...])
```

- **零重复参数**：`ids_only` 是 `list_media` 的第 26 个 query 参数，不用为 `/ids` 再写一遍 25 个筛选参数；
- **零漂移**：ids 与 `total` 共用同一个 `query`，不会出现"数了 874 条却返回 800 个 id"；
- **不分页**：`page` / `page_size` 被忽略（每页上限 200 会让全选变成 5 次往返）。

### 前端：全选 + 分片提交

- 结果跨页时表格上方出现「全选筛选结果（N 项）」；选中后显示「已选中全部 N 项（含跨页）」+ 取消全选；
- **分片**：后端 `media_ids` 有 `max_length=1000`（Pydantic，超了 422），`lib/media/batch.ts` 的
  `chunkIds()` 按 1000 切片顺序提交并聚合结果；批处理栏显示「处理中 800/2400」；
- **撤销名单只收真正成功的 id**：分片后部分失败时从每片剔除失败项，撤销不会去恢复本来没删掉的记录。

### 测试

| 层 | 覆盖 |
|---|---|
| 后端 `tests/test_media_ids_only.py` | ids 数 == total 且忽略分页；ids 严格跟随筛选；超上限 413 且提示含"筛选"（monkeypatch `MAX_IDS_ONLY=2`） |
| 前端 `lib/media/batch.test.ts` | 整除无空尾片、余数片、空选集、顺序保持、非正 size、默认 1000 |

### 顺带修掉的缺陷

`selectAllMatching` 原本用 `e.message` 提示，而 `ApiError.message` 是 `"API GET /media failed: 413"`——
后端那句可操作的中文在 `body.detail` 里，用户看不到。已统一改用 `errorMessage()`（优先取 `detail`），
工作台四处 catch 全部替换。

## 7. 列显示 / 隐藏 + 列配置持久化（已完成）

### 为什么是"配置"而不是"微调"

列宽拖拽早就有了（`vitoice.assets.colwidths`），但那是**微调**：双击表头重置即可。
列可见性是**配置**：小窗口下"标签""资源库"这些列其实可以整列关掉，而不该靠 `collapseAt` 的
断点媒体查询被动消失。两者语义不同，所以分开存（`vitoice.assets.hiddencols`），重置按钮也分开。

### 结构

| 文件 | 职责 |
|---|---|
| `lib/media/columns.ts` | 列定义加 `hideable`；新增纯函数 `visibleColumns()` / `gridTemplate()` |
| `lib/media/columnPrefs.svelte.ts` | 共享偏好 store：`hidden`、`isVisible()`、`toggle()`、`reset()`，读写 localStorage |
| `AssetsTable.svelte` | `cols = $derived(visibleColumns(...))`；表头遍历 `cols`；每行单元格按 `isVisible` 条件渲染 |
| `AssetsToolbar.svelte` | 第二行「列」按钮 + 复选面板（含"恢复默认"），隐藏列数显示在按钮上 |

### 两个刻意的约束

1. **`asset` 与 `actions` 不可隐藏。** 去掉标题/封面就没有入口，去掉操作就没有按钮——表会变成
   只能看的死列表。`visibleColumns()` 里对不可隐藏列做了强制保留，即使 localStorage 里被手改也不会生效。
2. **未知列 id 一律忽略。** 以后改列名时，用户浏览器里存的旧配置不该让表格渲染成空表。

### 共享 store 而不是 props

「列」菜单在工具栏、消费方在表格，两处必须读同一份状态；用 props 传递会把
AssetsWorkspace 变成列偏好的中转站。store 里用 `$state` + 整体替换 Set，`$derived` 能正常追踪。

### 测试（`lib/media/columns.test.ts`，9 个用例）

| 用例 | 防的是什么 |
|---|---|
| 默认显示全部 / 隐藏后少两列 | 基本行为 |
| 传 `asset`/`actions` 也不能被隐藏 | 表变成死列表 |
| 未知 id 被忽略 | 旧 localStorage 让表空白 |
| 所有可隐藏列都隐藏后仍剩 `asset+actions` | 极端配置下表格仍可用 |
| 模板由传入列生成、且与默认模板不同 | **表头/行错位**（模板来自默认列、单元格来自可见列） |
| 隐藏中间列后首尾轨道不变 | 顺序稳定 |
| `HIDEABLE_COLUMNS` 不含两个固定列 | 菜单不会出现不该有的勾选项 |

### 验证口径（诚实说明）

- 类型检查 0 error / 0 warning；99 个前端测试全过；`svelte-check` 覆盖了模板绑定与 store 类型。
- 「列」面板的**点击开合**没有做浏览器自动点击验证（headless 截图不能点）；
  逻辑由 `visibleColumns` 单测 + 模板条件渲染的静态检查覆盖。

## 8. 键盘操作（已完成）

### 键位

| 键 | 动作 |
|---|---|
| `j` / `↓` | 下一条（移动光标，不改变选中） |
| `k` / `↑` | 上一条 |
| `空格` | 切换当前行选中 |
| `x` | 全选 / 取消全选本页 |
| `Enter` | 打开详情 |
| `e` | 编辑 |
| `i` | 忽略 / 恢复刮削 |

带 `Ctrl/Cmd/Alt` 的组合键一律放行给浏览器；页脚有 `j/k 移动 · 空格 选中 · x 全选 · Enter 打开` 的提示。

### 关键设计：光标 ≠ 选中

`j/k` 只移动"光标"（左侧 2px 强调条 + 淡背景），`空格` 才切换选中。
如果把浏览和选中绑在一起，翻看长列表时会一路误选，清理比享受成本更高。

### 四个必须处理的边界

1. **输入框里打字不能抢键**：在搜索框打 `j` 不该把光标移走——`isEditableTarget()` 判断
   `INPUT/TEXTAREA/SELECT/contenteditable` 后直接放行。
2. **模态框打开时表格键位失效**：`document.querySelector('[role="dialog"][aria-modal="true"]')`
   存在时直接 return，否则 `x` 会在对话框背后全选。
3. **行内已消费的按键不二次处理**：行本身可聚焦（`tabindex="0"`），`Enter`/`空格` 由行处理器
   `preventDefault` 后，窗口级处理器看到 `e.defaultPrevented` 就退出，避免"打开两次/选中两次"。
4. **首尾不环绕**：`moveCursor()` 在边界停住，比"从末尾跳回开头"更符合表格直觉。

### 结构

| 文件 | 职责 |
|---|---|
| `lib/media/keyboardNav.ts` | 纯函数：`resolveNavKey()` / `moveCursor()` / `isEditableTarget()` |
| `lib/media/keyboardNav.test.ts` | 13 个用例：键位映射、修饰键放行、空列表、边界不环绕、可编辑目标识别 |
| `AssetsTable.svelte` | `cursor` 状态、`svelte:window` 监听、行 `data-row-index` + `scrollIntoView({block:'nearest'})` |
| `AssetsWorkspace.svelte` | 页脚键位提示 |

### 验证口径

- 单元测试覆盖键位与光标算法；`svelte-check` 0/0；`npm run build` 通过；页脚提示已用真机截图确认。
- **实际按键行为没有做端到端自动验证**（headless 无法注入键盘事件到该页面），
  逻辑正确性由纯函数单测 + 事件处理顺序的代码审查保证。

## 9. 虚拟滚动（已完成，但先说清适用边界）

### 一个必须承认的事实

实现过程中查了运行数据：**表格每页只有 50 行**（服务端分页，874 条 = 18 页）。
也就是说虚拟滚动在当前架构下**永远不会触发**——真正保护性能的是分页，不是虚拟化。

那为什么还是实现了：如果哪天把 `page_size` 提到 200、或改成"游标分页 + 累积"、
或把同一套逻辑复用到"一次加载全部"的时间轴视图，行数会真的到几千。
届时需要的正是这段代码，而不是重新设计。

### 实现

| 部分 | 说明 |
|---|---|
| `lib/media/virtualWindow.ts` | 纯函数 `computeWindow()`：返回 `start/end/padTop/padBottom` |
| `AssetsTable.svelte` | 外层 `.body` 作为滚动容器传入；`scrollTop/viewportH/headH` 三个测量值驱动窗口 |
| 占位 | 上下各渲染一个 `div.vpad` 撑出未渲染行的高度，滚动条长度保持真实 |
| 行高 | 固定 `72px`（CSS `min-height` 与脚本 `ROW_H` 必须一致，两处都有注释互相提醒） |

### 三个容易踩的坑（都已在代码里处理）

1. **吸顶表头占高**：窗口起点要减 `headHeight`，否则滚动后第一行被表头盖住。
2. **键盘光标行可能没渲染**：`scrollIntoView` 找不到 DOM 节点，改为按行高直接算
   `scroller.scrollTop`。
3. **行高不一致**：CSS 与 JS 必须同一个值；`padding + thumb + border` 算错会表现为
   "滚到底少一行"。

### 测试（`lib/media/virtualWindow.test.ts`，9 个用例）

中段窗口有界、`padTop + 窗口行数 + padBottom == total`、顶部无上垫片、底部 clamp 不越界、
空列表、短于视口的列表、极小列表不出现 `start > end`、`rowHeight = 0` 不除零、overscan 增大窗口。

### 阈值

`items.length > 200` 且传入滚动容器时才虚拟化；否则全量渲染——虚拟化会让 Ctrl+F、
打印、屏幕阅读器失真，874 条以内不值得付这个代价（而实际每页只有 50 条）。

## 10. 自定义筛选（已完成）

### 与内置 7 个视图的分工

内置视图是"服务端口径"的固定语义（有问题 / 缺封面 / 无标签…），改不了；
自定义筛选是用户自己拼的组合（库 + 目录 + 评分区间 + 搜索词 + 排序），存成命名快捷方式。
比如「AZV 里没封面且评分≥4」——这在任何内置视图里都表达不出来。

### 关键设计：存什么、不存什么

| 存 | 不存 |
|---|---|
| `view/libraryId/dir/section/genre/country/year/resolution/duration/ratingMin/attribute/tags/tagMatch/tagTypeId/source/q/sort/order` | `page`、`pageSize`、`display` |

- 存 `page` → 点开筛选取到的却是第 7 页（必须回到第 1 页）；
- 存 `display` → 你在表格里保存的筛选会把别人的网格视图强行切掉。

### "应用"的语义是重建而不是合并

`applyFilter()` 先把所有筛选字段**重置为默认**，再套快照。否则快照里没有的条件会
从当前状态泄漏进来，"保存一个不带目录筛选的视图"永远无法实现。测试专门覆盖了这一点。

### 结构

| 文件 | 职责 |
|---|---|
| `lib/media/savedFilters.ts` | 纯逻辑：`FILTER_FIELDS`、`toFilterState`、`applyFilter`、`isSavedFilter`、`normalizeName` |
| `lib/media/savedFilters.svelte.ts` | store：localStorage `vitoice.assets.savedfilters`，同名覆盖、上限 30 条 |
| `AssetsToolbar.svelte` | 「我的筛选 (N)」下拉：应用 / 删除 / 保存当前筛选（内联命名，Enter 保存、Esc 取消） |

### 踩到的坑：`bind:value` 不能绑 nullable

第一版用 `let savingName = $state<string | null>(null)` 直接 `bind:value={savingName}`，
**`svelte-check` 报 0 error，但运行时抛 `bind_invalid_value` 并有红色错误覆盖层**。
改成 `savingOpen: boolean` + `savingText: string` 两个状态后正常。
教训：svelte-check 不覆盖所有运行期绑定约束，UI 改动必须至少真机看一眼。

### 测试（`lib/media/savedFilters.test.ts`，11 个用例）

## 11. 批量取消 / 重复合并 / 目录统计 / 容量趋势 / 请求重试（已完成）

### 11.1 批量操作进度与取消

跨页全选后一次可能处理几千条，只显示"处理中"而没有"停"是不负责任的。

- `client.post` 增加可选 third param `{ signal }`，取消能中断**在途**请求，而不只是等下一片；
- `runBatch` 用 `AbortController` 驱动分片循环，批处理栏显示「处理中 800/2400」+「取消」；
- 取消是 `warn` 而不是 `err`：已完成的部分照常提交，提示写明「完成 N 项，剩余 M 项未处理」；
- toast 增加了第三档 `warn`（`ToastTone = 'ok' | 'err' | 'warn'`），语义上"部分完成"不是失败。

### 11.2 重复检测的合并动作

`DuplicatesDialog` 原本能查重、能选保留项、能清理，但**点一下就把上百条删了**，没有确认也没有撤销。
本轮补的是"安全边界"而不是新算法：

- 二次确认（`ConfirmDialog`）写明"每组保留你选中的那一份"与"可从回收站恢复"；
- 清理后走共享 toast，带「撤销」动作（逐条 `POST /recycle-bin/{id}/restore`）；
- 文案改成"已合并：保留 N 份，M 个重复项移入回收站"，让用户知道**保留**了多少。

合并策略保持"默认保留最大文件"（后端已按 size desc 排序），用户可改选。

### 11.3 目录级统计

`GET /api/libraries/{id}/tree` 的目录节点新增三个字段：

| 字段 | 口径 |
|---|---|
| `media_count` | 该目录**递归含子目录**的媒体数 |
| `missing_count` | 其中文件缺失的条数 |
| `no_poster_count` | 其中无封面/缩略图的条数 |

实现：一次查询取回该库所有 `(file_path, file_missing, poster_path, thumbnail_path)`，
在内存里按"归一化路径前缀"累加（`_dir_stats()`）。比逐目录查 SQL 少 N 次往返；
库内有几十万条时应改成 SQL 侧聚合，当前量级（千）不必要。

前端：目录行的计数优先显示 `media_count`（回退 `child_count`），并在 `missing_count > 0`
时追加一个红色小徽标（title 说明"其中 N 条文件缺失"）。

### 11.4 库容量趋势

容量是"时点事实"，不留点就无法回答"哪个库上周涨了 200GB"。

- 新表 `library_size_snapshots`（迁移 `021`）：`library_id + captured_on` 唯一，
  同一天重复读取只更新不堆积；字段 `media_count / total_size / missing_count`；
- 记录时机：`GET /api/libraries` 时顺手写入当天快照（**幂等**）。放在读取而不是扫描任务里，
  是因为扫描可能几天不跑，趋势需要连续的点；快照失败被吞掉，不能影响库列表；
- 新接口 `GET /api/libraries/size-history?days=30` → `{ series: { 库id: [{date, total_size, ...}] } }`；
- 前端在资源库状态页每行加 64×16 的折线（`sparkPoints()` 纯函数）+ 30 天变化文案；
  数据不足 2 点显示「—」和「数据积累中」，而不是画一条假线。

**注意**：刚上线时只有一个点，需要几天使用后曲线才有意义——这是设计使然，不是 bug。

### 11.5 列表请求的超时与重试

`createMediaList` 原来直接 `await mediaApi.list()`：后端卡住时前端无限转圈，一次网络抖动就让列表变空。

`lib/media/listRequest.ts`：

| 规则 | 值 | 理由 |
|---|---|---|
| 超时 | 15s（`withTimeout`） | 超过即按可重试错误处理 |
| 重试 | 最多 2 次尝试（1 次重试），间隔 600ms | 幂等 GET；不把"慢"变成连环请求 |
| 不重试 | 4xx / 用户取消 | 参数错误重试也不会变对；取消不该被报成失败 |

`useMediaList` 的 `reqId` 竞态保护保留：重试期间若有更新的请求，旧重试直接退出。

## 12. 侧边栏与右侧内容联动修复（用户反馈，已完成）

### 症状

管理页「侧边栏 ↔ 右侧列表」状态不一致。实测复现出两条独立缺陷。

### 缺陷 1：换库不清目录（右侧列表变空、面包屑还挂着旧目录）

目录是"某库内的相对路径"。用户在工具栏把库从 AZV 换成「柯南」后，`dir=A` 仍留在状态里：

- 请求变成 `library_id=1 & dir=A` → 柯南库里没有 `A`，列表**空**；
- 面包屑显示「柯南 › A」——一个不存在的路径；
- 再切回 AZV，`dir=A` 又"复活"，用户会以为筛选被记住了。

根因：`patch()` 只做浅合并，而**改 libraryId 的地方有三处**（工具栏下拉、侧栏树、批量操作），
每处各自记得清 `dir` 是不可能的。修法是把规则下沉到纯函数 `applyPatch()`：

```
partial 里 libraryId 变了 且 没显式给 dir  → 清空 dir
libraryId 变成空                          → 清空 dir
```

### 缺陷 2：点侧栏目录会把右侧筛选全清掉

`DirectoryTree` 的 `gotoDirectory()` 从零拼 URL：

```ts
`/manage?section=assets&lib=${libId}&dir=${encodeURIComponent(relPath)}`
```

于是右侧的**搜索词 / 视图 / 标签 / 评分区间 / 排序 / 显示模式全部丢失**。
用户感受就是"点一下侧栏文件夹，右侧筛选莫名被重置"。

修法：在当前查询参数上合并（`realSearchParams()`），只改 `lib/dir/section` 并删掉 `page`。
同一函数里的"点文件"分支（带 `sel`）有一模一样的问题，一并修了。

### 缺陷 3：切 section 残留资产参数（顺手修）

`switchSection()` 原来保留全部 query，只删 `view/display`。切到「标签治理」后 URL 里还躺着
`lib=5&dir=A&q=...`——虽然标签页不用它们，但一旦回到资产页就"诈尸"，且侧栏树会误显示选中态。

改为：切 section 只保留 `section`；并且**点击当前已激活的项不再做任何跳转**
（否则会把用户刚调好的筛选清空，是很讨厌的意外）。

### 另外：dir 依附于库（URL 两侧都加了约束）

- `parseMediaQuery`：没有 `lib` 时 `dir` 一律视为空（旧链接不会偷偷生效）；
- `serializeMediaQuery`：没有 `lib` 时不写 `dir`（避免残留值在下次选库时突然生效）。

写了一个临时自检页（同源 iframe 载入 `/manage` 并用 JS 点击/派发 change），
跑完 12 条断言后删除。结果（修复后）：
