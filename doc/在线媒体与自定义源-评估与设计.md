## 1. 四个参考项目评估

| 项目 | 技术栈 / 许可 | 与我们的关系 | 值得借鉴 | 能直接抄吗 |
|---|---|---|---|---|
| **Peach**（peach-mitao/peach，6.8k★） | Python + React，AGPL-3.0 | **最接近**：单用户本地优先媒体系统，本地 + 网盘统一馆藏 | 网盘挂载即本地库、云下载（115/PikPak）、跨站关注（FANBOX/Patreon/Kemono）、浏览器脚本识别番号一键入库、按番号搜字幕（SubtitleCat）、长任务断点续跑、整理前预览且可撤回上一批、外部播放器接力 | **否**（AGPL 传染） |
| **Amane**（sqzw-x/amane） | Python + Node，GPLv3 | 同类本地影库 | **多源逐字段择优**（一部片：标题取 A、封面取 B、演员取并集）、命名/整理规则引擎、海报超分、自然语言智能体 | **否**（GPL） |
| **LibreTV**（LibreSpark/LibreTV） | Next.js + TS，聚合站 | 形态不同（无本地库），但**源聚合机制**是范本 | 苹果 CMS v10 采集站协议、跨源同名聚合、换源测速、**源健康度阶梯停用**（30min→24h→长期）、源订阅 JSON / TVBOX 配置、HLS + 跳过片头片尾、IPTV M3U + EPG | 协议与机制可自实现 |
| javbus 论坛帖（tid=177676） | 论坛 | **无法评估**：需登录，抓取被重定向到登录页，正文不可得 | — | — |

结论：**协议与机制可以学，代码不能抄**（vitoice 是 MIT，AGPL/GPL 代码合进来会改变整个项目的许可）。
本轮的实现全部是自写的：采集站协议是公开事实标准，熔断/聚合是通用工程模式。

## 2. vitoice 现状盘点（开工前）

已有：
- `media_type=NETWORK/BOTH` 的媒体模型 + `MediaUrl` 多源地址 + `network_sources.py`（内置成人站聚合解析 fancode → HLS）；
- 播放器已接 hls.js（但**从 CDN 加载**，离线不可用）、多源切换、片段标记（segments）；
- `/media/import-network` 可把 URL 入库为网络媒体；
- `scrape_sources` 配置 + `test_scrape_source` 探活（仅元数据刮削，不涉及播放）。

缺：
- 通用的「用户自填在线源」——只有一个硬编码的站点实现；
- 聚合搜索 + 同名合并；
- 源健康度 / 熔断；
- 在线播放的入口页面（除详情页里针对已入库媒体的解析）。

## 3. 本轮已实现

### 3.1 后端：源适配层

`app/services/media_sources.py`（纯逻辑 + 单源抓取，430+ 行，无 FastAPI 依赖以便单测）：

| 能力 | 说明 |
|---|---|
| 源配置 | `MediaSource{id,name,base_url,api_path,kind,enabled,timeout,headers}`；`validate_source` 逐字段校验并给中文原因 |
| 采集站协议 | 苹果 CMS v10 `ac=detail&wd=` 搜索 / `ac=detail&ids=` 详情；解析 `$$$` 线路与 `#` 集数 |
| 标题归一化 | 剥清晰度/字幕/语言噪声、**剥内嵌年份**、去标点小写（否则「沙丘 2021 1080P」与「沙丘」不合并） |
| 跨源聚合 | 按（归一化标题 + 年份）合并；年份缺失按通配处理：同标题只有一个已知年份时并入，多个候选时单独成组（不把 1984/2021 的两部《沙丘》错并） |
| 源健康度 | `failed 3 次 → 30min`、`4 次 → 24h`、`≥5 次 → 7 天` 熔断；成功一次立即恢复 |
| 直链判定 | `.m3u8/.mp4/.flv/...` 视为可直接播放，其余（原站页面）标记 `direct=false` 交给浏览器打开 |

`app/services/media_sources_store.py`：配置读写（settings JSON）、健康度持久化、**并发聚合搜索**（单源失败只降权不影响整体）、探活。

`app/api/media_sources.py`：`GET/PUT /api/sources`、`POST /api/sources/test`、`GET /api/sources/search`、`POST /api/sources/resolve`。

### 3.2 前端：`/online` 在线片库

- 聚合搜索（`?q=` 深链可直接带结果）；
- 结果卡片显示「N 个源 · M 条线路」，展开后逐源、逐线路、逐集选择；
- 直链集数 → 内嵌播放（hls.js 用 **npm 依赖**，不走 CDN，离线可用）；非直链 → 打开原站；
- 播放层内可直接「入库」为网络媒体（选目标库）；
- 源管理面板：新增 / 探活 / 启停 / 删除，带健康度与熔断状态；
- 顶栏新增「在线」入口。

## 4. 过程中修掉的两个真 bug（都是本轮实测撞出来的）

1. **系统代理把本地地址也代理了**。`fetch_cms` 复用全局 `get_proxy_url()`，而本机确实配置了代理
   `http://127.0.0.1:11423` —— 结果访问 `127.0.0.1:18765` 直接 `ConnectError`。
   修法：新增 `is_local_host()`（接受 URL 或主机名，判断 loopback/private/link-local），
   本地与局域网源**直连**。这条对用户意义很大：NAS 上的采集站和本地测试源都靠它。

2. **标题里的年份没有剥掉**。`「沙丘 2021 1080P」` 与 `「沙丘」` 归一化成两个 key，跨源合并失效。
   修法：归一化阶段剥内嵌年份，年份只作为分组的一个维度。

（另外修了 `virtualWindow.test.ts` 缺失 `scrollTop` 导致 svelte-check 报错的基线问题。）

## 5. 后续路线

### 第一期（下一步，1~2 天量级）
- **入库时保留线路信息**：现在入库只存第一条 URL；应把「源 + 线路 + 集数」写进 `MediaUrl`，详情页可直接换源播放（复用已有 `activeSourceIdx`）。
- **播放进度接入**：在线播放目前不写 `playback_position`；接上后可与本地媒体共用「继续观看」。
- **源订阅**：支持粘贴一份源列表 JSON 批量导入（LibreTV 的 LibreTV-SourceList 格式），省得一个个填。

### 第二期（本地管理强化，对标 Amane）
- **多源逐字段择优**：刮削结果按字段合并而不是整条覆盖，且手动修改不被覆盖。
- **命名/整理规则引擎**：模板 + 预览 + 可撤回上一批（我们已有 rename 模板与批次概念）。
- **外部播放器接力**：mpv/PotPlayer 打开并定位到当前时间。

### 第三期（可选）
- IPTV / M3U + EPG（LibreTV 形态，独立「直播」section）；
- 字幕搜索（Peach 的 SubtitleCat 思路）；
- 浏览器脚本一键入库（需配对 token，注意安全边界）。

## 6. 合规与安全边界

- **许可**：Peach(AGPL-3.0)、Amane(GPLv3)、LibreTV 的代码都不合入（MIT 项目），只借鉴机制。
- **SSRF**：源地址统一走 `validate_http_url`，`api_path` 强制相对路径；本地/局域网地址允许（单用户本机场景）。
- **内容**：聚合源只返回第三方接口的结果，不存储、不转码；成人源仍受既有 `network_allow_adult` / `show_restricted` 开关隔离。
- **凭据**：不保存任何采集站账号；只有用户自己填的接口地址与可选 headers。
